# HabitLoop Product Direction

HabitLoop is not a game and not a preset-template gallery. It is a calm daily operating layer for routines: decide what matters, see what is due, check in quickly, understand patterns, and recover without shame.

## Implemented product areas

- **Today:** scheduled routines, progress, completion and rest days.
- **Habits:** custom routine creation, weekday schedules and detail history.
- **Insights:** weekly activity chart, momentum, seven-day activity, strongest routine, recovery and schedule-aware consistency graphics.
- **Profile:** identity, overall progress, freezes, sync state, security and preference entry points.
- **Account & security:** local/cloud data explanation, masked anonymous backup identity, safe cloud sign-out and reconnect controls.
- **Challenges:** curated public-format challenges that create real private routines, with no fabricated activity or participant counts.
- **Advertising:** rewarded ads are limited to freeze earning; a labeled banner appears only after Challenge discovery content.
- **Streak protection:** explicit rewarded-ad readiness, retry and persisted rewards.
- **Settings:** reminder time and local-first product information.
- **Onboarding:** identity, custom first routine, product walkthrough and contextual notification permission.
- **Replayable guide:** a permanent six-part explanation of Today, Habits, Trends, Together, rewards and Profile.

## Next useful screens, in recommended order

### 1. Edit routine

Allow name, schedule, reason and category changes without deleting progress. This is the highest-priority missing lifecycle action.

### 2. Pause and archive

Users should be able to take a break without destroying history. Archived routines belong in a separate management screen and can be restored.

### 3. Calendar history

A full-month view with scheduled, completed, missed and protected states. This must distinguish an unscheduled day from a miss.

### 4. Weekly review

A focused review with planned versus completed occurrences, one positive pattern and one small adjustment. Avoid generic “AI coaching” claims.

### 5. Reminder per routine

Global reminders are simple, but medication, exercise and reading often need different cues. Add per-routine time only after the schedule model is stable.

### 6. Data and privacy

Export completion history, explain cloud backup, delete cloud data and provide account upgrade when cross-device identity is introduced.

## Features intentionally deferred

- Public leaderboards: poor fit for private or health-related routines.
- Open public feeds: deferred until recoverable accounts, reporting, blocking, moderation and production Firestore rules exist.
- Unlimited badges: decorative unless tied to meaningful recovery or consistency.
- Generative coaching: should not be added until the app has trustworthy schedule-aware statistics and clear safety boundaries.

## Product principles

1. A user’s own words define the habit; templates only help presentation.
2. Unscheduled is not missed.
3. Recovery is more useful than punishment.
4. Every number must be explainable from local data.
5. Ads appear only inside an intentional reward exchange.
6. The primary daily action should remain reachable in one tap.
